# Contributing

Thanks for looking. Issues and pull requests are welcome.

## Setup

```bash
uv sync
```

## Before you open a pull request

Run the same gates CI runs. All of them must pass with no warnings:

```bash
uv run ruff check .
uv run ruff format --check .
uv run mypy src tests
uv run pytest
uv run kyc-eval --gate
uv run python tools/license_audit.py
```

## Rules that matter here

- **A new check needs a scenario.** Add a case to `src/kyc/generator.py` that the check exists to catch, label its
  expected outcome, and confirm `kyc-eval --gate` fails without your check and passes with it.
- **Nothing approves on a score.** A check returns pass only on evidence that can be re-run; similarity scores may
  label a failure but not pass it (ADR 0003, ADR 0004).
- **No real personal data.** Specimens use the invented names in `PEOPLE`, carry a SPECIMEN mark, and never copy a
  real document's layout closely enough to be mistaken for one.
- **Permissive licences only.** `tools/license_audit.py` fails on GPL, LGPL, AGPL or anything unidentified. A new
  dependency also needs a line in ADR 0006 or a new ADR.
- **Generated bytes are pinned.** If you change the generator, update the digest in
  `tests/unit/test_generator_and_eval.py` and say why in the pull request.
- **Decisions get an ADR.** Number it after the last one, keep it to a page, and name what was given up.
